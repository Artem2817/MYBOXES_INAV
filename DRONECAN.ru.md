## INAV 10 r16: DroneCAN и MATEK M10Q-3100

Основа — INAV 10.0.0-rc2, определения всех трёх плат перенесены из r15. Это предварительный выпуск INAV 10. Нужен INAV Configurator 10.0; для старых образов 9.1 используйте Configurator 9.1.

### Заводской профиль: GPS и компас одним кабелем

После чистой установки r16 для Mini v1, Mini v2 и Mini v2 VIB заданы:
- CAN1 (`dronecan_bus = 1`), 1000 кбит/с;
- ID полётника 1, DNA-сервер включён;
- функция GPS включена, `gps_provider = DRONECAN`;
- `mag_hardware = DRONECAN`;
- обычный PWM для моторов, DShot выбирается отдельно;
- поворот IMU Mini v1 из r15: 180° по крену.

Профиль рассчитан на MATEK M10Q-3100 со штатной AP_Periph MatekL431-GPS. Один модуль передаёт GPS и RM3100-компас по общей шине. На полётнике выбирается DRONECAN, а не локальный RM3100 по I²C/SPI.

Перед переходом с 9.x сохраните Backup Config в Firmware Flasher Configurator 10.0 и прошейте HEX с Full Chip Erase. Restore Config заменяет заводские значения сохранёнными настройками. Для заводского профиля Matek не восстанавливайте поверх него старые GPS/UART/MAG-настройки без проверки.

### Подключение MATEK M10Q-3100

Это AP_Periph-узел с u-blox M10 и RM3100. CAN и UART/MSP — разные интерфейсы. Пример относится к M10Q-3100; полное обозначение проверяйте на модуле, не по сокращённому названию магазина.

| M10Q-3100 | MYBOX Mini |
|---|---|
| 5V | Питание 5V, фактически 4,5–5,3 В |
| G / GND | GND |
| C-H / CAN-H | CAN-H выбранного порта |
| C-L / CAN-L | CAN-L того же порта |

Перечислены сигналы, а не порядок контактов в разъёме. Проверяйте маркировку кабеля. TX2 при CAN-подключении не используется. Убедитесь, что CAN-разъём получает питание: USB полётника не на всех схемах питает внешний модуль.

Терминация — 120 Ом на двух физических концах шины. На обесточенной шине между CAN-H и CAN-L ожидается около 60 Ом при двух терминаторах. Не добавляйте резисторы, если они уже установлены на обоих концах.

Для автоматического подключения модуль должен использовать DroneCAN 1 Мбит/с и поддерживать DNA. Если назначен статический ID, он должен отличаться от ID полётника 1. Прошивка полётника не перепрошивает модуль и не исправляет его ранее изменённые настройки. Появление узла и получение спутникового 3D Fix — разные этапы.

### Выбор CAN1 или CAN2

Одновременно активен один интерфейс. Выбор сохраняется после `save` и перезагрузки. GPS и CAN-компас используют общий выбранный интерфейс.

Переставьте кабель на CAN2 и задайте:

```text
set dronecan_bus = 2
save
```

Вернуть CAN1:

```text
set dronecan_bus = 1
save
```

| Плата | CAN1 RX / TX / Silent | CAN2 RX / TX / Silent |
|---|---|---|
| Mini v1 | PD0 / PD1 / PB3 | PD9 / PD10 / отдельный Silent не задан в hwdef |
| Mini v2 | PD0 / PD1 / PA8 | PB5 / PB6 / PD7 |
| Mini v2 VIB | PD0 / PD1 / PA8 | PB5 / PB6 / PD7 |

Это выводы STM32 из hwdef для проверки платы. Модуль подключается к CAN-H/CAN-L после трансивера, не к этим выводам MCU.

### GPS и компас вместе на CAN1

Это заводской режим. Для уже настроенной платы его можно восстановить без сброса остальных параметров:

```text
feature GPS
set dronecan_bus = 1
set dronecan_bitrate_kbps = 1000
set dronecan_node_id = 1
set dronecan_use_dna_server = ON
set gps_provider = DRONECAN
set mag_hardware = DRONECAN
save
```

Для обоих датчиков на CAN2 используйте `dronecan_bus = 2`. Назначать GPS на UART в Ports для CAN-модуля не требуется.

### Только GPS по CAN, компас выключен

Полётник будет использовать только GPS, даже если Matek продолжает передавать оба датчика:

```text
feature GPS
set dronecan_bus = 1
set gps_provider = DRONECAN
set mag_hardware = NONE
save
```

Для отдельного компаса на I²C вместо NONE задайте `mag_hardware = AUTO`, подключите его к назначенной внешней I²C-шине и проверьте MAG. Автопоиск не подменяет его CAN-компасом.

### Только компас по CAN, GPS выключен

```text
feature -GPS
set dronecan_bus = 1
set mag_hardware = DRONECAN
save
```

Для отдельного GPS по UART включите `feature GPS`, задайте `gps_provider = UBLOX` и назначьте GPS нужному UART в Ports. CAN-компас при этом сохраняется. Для UART/MSP-выхода Matek нельзя выбирать UBLOX: это другой протокол.

### GPS по UART/MSP и компас по CAN от одного M10Q-3100

У M10Q-3100 TX2 передаёт MSP, не обычный UBX. Оставьте CAN-H/CAN-L, общее питание и GND; дополнительно соедините TX2 модуля с RX свободного UART полётника. Питание модуля достаточно подать один раз.

В Ports для этого UART включите MSP на 115200. Функцию GPS на этом UART не назначайте. На модуле должен быть включён выход UART/MSP, как в инструкции Matek. В полётнике измените источник GPS:

```text
feature GPS
set gps_provider = MSP
set mag_hardware = DRONECAN
save
```

Выбранный dronecan_bus и скорость CAN сохраняются. Полётник получает GPS по MSP, а компас по CAN; это работает в r16 INAV 10. В r15 INAV 9 компаса DroneCAN нет. Команда gps_provider = UBLOX для TX2 этого Matek не подходит.

### GPS на CAN1, компас на CAN2

В r16 такой вариант недоступен: `dronecan_bus` выбирает один общий физический интерфейс. Разместите оба датчика на CAN1, оба на CAN2 либо сочетайте CAN с отдельными UART/I²C. Несколько CAN-устройств на выбранной шине допустимы при разных ID. Два интерфейса одновременно этот режим драйвера не обслуживает.

### Проверка после подключения

В Configurator 10.0 откройте DroneCAN: должен появиться узел Matek. В CLI:

```text
get dronecan_bus
get dronecan_bitrate_kbps
get gps_provider
get mag_hardware
status
```

Ожидаются выбранная шина, 1000 кбит/с, DRONECAN для обоих датчиков и MAG=OK после поступления данных. Проверьте обновление координат и спутников; 3D Fix получают на открытом месте. Если узел есть, а MAG нет, проверьте передачу магнитометра на самом AP_Periph-узле.

Поддержаны MagneticFieldStrength 1001, MagneticFieldStrength2 1002 и HiRes 1043 AP_Periph. Гаусс преобразуются в миллигаусс. Без обновлений более 500 мс компас перестаёт считаться исправным. Первая корректная пара node ID / sensor ID фиксируется до перезапуска, чтобы не смешивать разные компасы.

После установки откалибруйте компас и проверьте курс при повороте модели. Не переносите `align_mag = CW90` из инструкции UART/MSP на CAN автоматически: это другой тракт данных. Выравнивание проверяют для фактического монтажа.

### Проверки сборки

Собраны три цели; пройдены программные тесты сообщений AP_Periph, масштаба, устаревания данных, выбора источника и GPIO CAN1/CAN2 по hwdef. Физическое получение GPS/компаса от конкретного M10Q-3100 в этой сборке ещё нужно подтвердить на стенде.
