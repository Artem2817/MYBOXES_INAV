# INAV для MYBOX H743 Mini

Основа сборки — [INAV 9.1.0](https://github.com/iNavFlight/inav/releases/tag/9.1.0), коммит `e519b69b02e27c8bdc03b4a0889f1baaae211a54`. У всех трёх ревизий STM32H743 с 2 МиБ flash и кварцем 8 МГц. Распиновка перенесена из [актуальных hwdef](../ardupilot_hwdef) и [проверки схемы v2](../diagnostics/mini_v2_current_2026-11-05/FINAL-SCHEMATIC-AUDIT.ru.md).

| Плата | Цель сборки | Гироскоп и акселерометр | Барометр | PWM | Аналоговый OSD |
|---|---|---|---|---|---|
| Mini | `MYBOXH743MINI` | ICM-42688-P, SPI1, CS `PC15` | MS5611, I²C1 `0x77` | 14 | SPI2 |
| Mini v2 | `MYBOXH743MINIV2` | ICM-45686, SPI2, CS `PB12` | SPA06-003, I²C1 `0x76`, драйвер SPL06 | 13 | SPI4 |
| Mini v2 Vib | `MYBOXH743MINIV2VIB_BENCH` | ICM-45686 на SPI2 и ICM-42670-P на SPI1 | SPA06-003 на I²C1, 0x76 и 0x77 | 13 | SPI4 |

Для Vib принят состав из итогового hwdef от 5 ноября 2026 года. Он указывает ICM-45686 на основной плате и ICM-42670-P на модуле J19. Ранний отчёт по другой схеме описывает обратную установку. У обоих IMU есть отдельное чтение и диагностика. В CLI `gyro_to_use` выбирает IMU и акселерометр для управления после перезапуска. Значение 0 соответствует основной плате, 1 — модулю. В r3 заводской выбор — 1, выносной модуль. Если выбранный IMU не обнаружен при загрузке, прошивка пробует второй. Калибровка акселерометра привязана к выбранному IMU. При переходе с r2 и при смене активного IMU проверьте оси и выполните шестипозиционную калибровку заново. Обновление сохраняет ранее записанный выбор. Для переноса заводского приоритета из r3 в существующие настройки задайте `gyro_to_use=1` и `mybox_baro_to_use=1`.

Оба барометра измеряют давление со своими коэффициентами. `mybox_baro_to_use` выбирает предпочтительный барометр при загрузке (0 — основная плата, 1 — модуль). Если при загрузке доступен один барометр, используется он. Заводской приоритет r3 — выносной барометр. Выбор остаётся фиксированным в полёте. `status` показывает предпочитаемые и фактически выбранные датчики, доступность обоих IMU и давление каждого барометра.

В обеих v2 `mybox_heater_target` задаёт температуру нагрева в градусах Цельсия. Заводское значение 0 держит нагрев выключенным. Обратная связь у обычной v2 берётся с ICM-45686, у Vib — с ICM-42670-P. PWM нагрева ограничен 20%. Для включения нужно подтвердить монтаж резисторов и проверить температуру на плате.

## Сборка в Ubuntu или WSL

Нужны `git`, `cmake`, `make`, `gcc`, `g++` и `ruby`. Если подходящего ARM GCC нет, INAV скачает рекомендованный Arm GNU Toolchain 13.2.Rel1 в свою копию исходников. Из каталога аппаратного проекта в Ubuntu или WSL выполните:

```bash
bash inav/build.sh ~/inav
```

Сценарий проверяет коммит, добавляет цели и собирает только три указанные прошивки. Для обеих v2 он применяет адаптацию SPL06 под SPA06-003. Она проверяет ID `0x11`, выбирает внутренний датчик температуры и учитывает дополнительные коэффициенты `c31` и `c40`. [Даташит SPA06-003, §4.6 и §7.10–7.11](https://cdn-shop.adafruit.com/product-files/6420/spa06-003.PDF).

Для I²C4 на v2 применяется правка выбора альтернативной функции. Линия SDA на `PB9` использует AF6, линия SCL на `PD12` — AF4.

На этой машине файлы проекта также лежат внутри WSL в `~/inav/mybox`. Повторная сборка оттуда:

```bash
bash ~/inav/mybox/build.sh ~/inav
```

Файлы `inav_9.1.0_*.hex` появятся в `~/inav/build-mybox`. По умолчанию используются четыре параллельных задания, число можно задать через `JOBS`.

## Первый запуск на стенде

1. Сохраните параметры ArduPilot и подходящий образ для возврата. Стандартный INAV HEX для H743 начинает запись с `0x08000000`, где находится загрузчик ArduPilot. Для перехода используйте аппаратный режим STM32 DFU и загрузку локального HEX в INAV Configurator 9.1. Для возврата через DFU нужен соответствующий ArduPilot `*_with_bl.hex` или комплект загрузчика и приложения для конкретной ревизии.
2. Проверьте связь по USB, определение IMU и барометра через `status`, направление всех трёх осей по модели в Configurator и показания ADC по измерениям. В исходниках задана ориентация `CW0_DEG` и перенесены коэффициенты напряжения и тока из hwdef.
3. Для проверки приёмника используйте USART2 TX/RX (`PD5`/`PD6`), по умолчанию выбран CRSF. GPS назначен на UART4 у Mini и USART1 у v2. У v2 выведены I²C1/2/4, внешний компас назначен на I²C2. Дополнительно проверьте OSD, карту microSD в режиме SDMMC и запись Blackbox.
4. С отключёнными моторами проверьте осциллографом порядок и форму сигналов PWM, включая комплементарные `PB14`/`PB15` у v2. Заводской протокол моторов — `STANDARD`. После восстановления настроек проверьте `get motor_pwm_protocol`. Для DShot потребуется отдельная настройка и проверка DMA на `TIM4_CH4` и `TIM15_CH2`, у которых в STM32H743 нет индивидуальных DMA-запросов.

CAN-трансиверы переведены в silent. Подогрев v2 включается через параметр целевой температуры. Встроенные safety-кнопка и светодиод safety и аппаратное управление потоком UART пока не задействованы. Зуммер назначен только у v2. Все три сборки предназначены для стендовой проверки.

## SBUS на выделенном RCIN

На всех трёх Mini выделенный контакт RCIN принимает SBUS 100 кбит/с. На Mini это PA3/TIM2_CH4, на обеих v2 — J10/1, PB3/TIM2_CH2.
Контакт используется для приёма. Приём PPM через RCIN в этой версии INAV не поддерживается. Для CRSF сохранён обычный UART.

В Configurator выберите последовательный приёмник SBUS. Затем в CLI включите выделенный вход:

```
set serialrx_provider = SBUS
set mybox_sbus_rcin = ON
save
```

Для стандартного инвертированного SBUS применяется заводское `serialrx_inverted=OFF`, как у штатного драйвера SBUS. После перезапуска проверьте каналы и failsafe при отключении приёмника. На v2 нагрев и RCIN используют разные каналы TIM2 и сохраняют отдельные функции.
