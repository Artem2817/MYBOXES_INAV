# Две линии MYBOXES INAV

## Рабочие каталоги

| Линия | Закреплённая основа | Проект в WSL | Полные исходники |
|---|---|---|---|
| inav-9 | INAV 9.1.0, e519b69b | ~/inav/mybox | ~/inav-9-failover |
| inav-10 | INAV 10.0.0-rc2, f1cd5c6f | ~/inav-10/mybox | ~/inav-10 |

Обе линии поддерживают Mini, Mini v2 и Mini v2 Vib. Ветка по умолчанию — inav-10; main сохранена для старых ссылок и не используется для новых выпусков.

Сейчас опубликованы: INAV 9 r15 Stable для трёх плат и r16 Dev только для Vib; INAV 10 r17 Dev для трёх плат и r18 Dev только для Vib. Статус конкретного выпуска не определяется именем ветки.

## Ежедневная работа

INAV 9:

```bash
cd ~/inav/mybox
git switch inav-9
git pull --ff-only
bash build.sh ~/inav-9-failover
```

INAV 10:

```bash
cd ~/inav-10/mybox
git switch inav-10
git pull --ff-only
bash build.sh ~/inav-10
```

HEX находятся в build-mybox соответствующего каталога полных исходников, если не задан BUILD_DIR. Старый ~/inav хранит диагностические изменения; не применяйте к нему reset/clean и не используйте его как чистую основу новой сборки.

Временные ветки создавайте от нужной линии, например codex/inav9-fix. Исправление для обеих версий переносите отдельным коммитом с адаптацией и проверками; целиком ветки не сливайте.

## Выпуск обновления

1. Проверьте текущие [Releases](https://github.com/Artem2817/MYBOXES_INAV/releases) для нужной линии и платы. Возьмите новый, ещё не занятый номер ревизии.
2. Откройте Actions → Publish Mini firmware (INAV 9 or 10), явно выберите inav-9 или inav-10.
3. Укажите новую ревизию. Текущий сценарий собирает и публикует три платы; выпуск только одной платы требует отдельного осознанного выбора состава.
4. Сценарий проверяет исходный коммит, собирает три цели, выполняет профильные проверки, проверяет HEX и SHA-256. Новый выпуск имеет канал Dev.
5. Сайт получает все опубликованные релизы обоих репозиториев автоматически.

Не заменяйте байты, файлы и теги опубликованных выпусков. Перевод проверенного выпуска в Stable выполняется отдельно с сохранением HEX и его SHA-256. Для исправлений используйте новый номер.

Манифест хранит source_branch, inav_major, upstream_release и точные коммиты проекта и INAV. Версия основы задаётся release-line.json; при обновлении меняют и тег, и полный коммит.

## Проверки и история

Изменения документации проходят быстрые проверки проекта. Изменения целей, активного патча, основы, сборки, упаковки и профильных тестов запускают полную проверку трёх плат. Ручной запуск релизного сценария всегда собирает прошивки.

Активная адаптация ядра — board-support.patch. Исторические отдельные патчи сохранены в archive/legacy-patches и не применяются build.sh. Старые теги продолжают ссылаться на свой исходный состав.
